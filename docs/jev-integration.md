# Jev integration

2026-09-21 Implemented the HTTP adapter according to the official documentation:
- https://docs.typesafe.ai/introduction/quickstart
- https://docs.typesafe.ai/api
- https://docs.typesafe.ai/primitives/choice

`majsoul/jev.py` passes the existing structured state into `state`, and converts all legal actions and features generated by the rule engine into Choice `criteria`. Uses `POST /v1/systemone`, Bearer authentication and the default model `jev-latest`. No screenshots are passed, and the model is not allowed to generate new actions.

The response must contain a legal choice, a complete probability distribution and a finite 0–1 confidence; the distribution must sum to 1 within floating-point tolerance, and the choice must be the maximum-probability option. After passing, the model name, action, probability and confidence are retained for use in the run log. Confidence is not win rate; a successful API call also does not prove Mahjong strategy strength.

## Local configuration

Write the following configuration in the project `.env`; fill in the key only locally, do not commit it or send it in chat:

```dotenv
TYPESAFE_API_KEY=your key
JEV_MODEL=jev-latest
JEV_BASE_URL=https://api.typesafe.ai
JEV_TIMEOUT_SECONDS=8
JEV_PROXY=http://127.0.0.1:7890
```

Process environment variables override the project `.env`. Jev does not read the reference project key, nor does it reuse `API_KEY`. The current Steam configuration is Jev via the local `7890` proxy, with HTTP/mixed using `http://127.0.0.1:7890`; SOCKS requires installing `httpx[socks]` and configuring `socks5://127.0.0.1:7890`. Jev only uses the explicit `JEV_PROXY` and does not inherit general proxy environment variables. If the proxy is not started, Jev requests will fail.

The `--policy` of `run` / `replay` can be `jev`, `deepseek`, `auto` and `efficiency`. `auto` prioritizes Jev; after the first failure it simultaneously rebuilds the Jev client to retry once and starts direct-connection DeepSeek as a fallback; whichever side first returns a legal action that passes verification wins, and the other request is cancelled and awaited to exit. If either branch fails or the action is illegal, it continues waiting for the other branch; only when both fail is a decision failure reported. The first request, the Jev retry and DeepSeek share the original absolute deadline; when the budget is exhausted, no recovery is started and the timer is not reset; stopping or a state change cancels the entire decision and its recovery requests. The next decision still prioritizes Jev. Here "restarting Jev" means rebuilding the local HTTP connection and re-requesting, not restarting the remote service or the local proxy process.

`timing.attempts` in `decisions.jsonl` stores each `backend`, `attempt`, `restarted`, `route`, status and elapsed time, and transport exceptions record the sanitized exception type; `selected_backend` and `selected_attempt` identify the winning request. In `jev` mode, failure directly reports an error, which is suitable for verifying the real integration and avoids fallback masking faults. `run` defaults to auto, and offline replay defaults to efficiency, to avoid unintentionally calling paid APIs.

The existing run/replay still belongs to the historical visual entry point: replay accepts observation JSONL, not the new ROI video recognition pipeline. The new scheme's ROI and single-frame visible tiles/metadata have been accepted, and the offline continuous-state core has also been implemented; however, the full-match event sequence has not yet passed, and the trigger and execution verification are still not connected, so automatic play cannot be started based on this.

The official recommendation is to split complex reasoning into atomic judgments. Here we follow the Choice(legal_actions) in the objective, using features already computed by the rule layer to reduce the model's burden; there is still no evidence that this single choice can reach the target strategy level, and it must be independently evaluated later, and the Choice probability must not be interpreted as deal-in probability or expected value.
